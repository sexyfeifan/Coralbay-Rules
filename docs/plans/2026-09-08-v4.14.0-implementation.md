# 4.14.0 实施细则：统一分流规则来源与可靠性修复

日期：2026-09-08。基线：4.13.0 / `9fee0ed1`。本文件是执行计划，完成情况以末尾验收记录和发布说明为准。

## 目标与范围

在两个资源页始终展示本机镜像与上游原文件，在 MihomoPro 覆写、PPanel 模板、普通订阅转换、自定义分流订阅中提供统一的“分流规则来源：本机镜像／上游源”。先修复[专项审查的九项问题](../../REVIEW-SOURCE-SWITCH-2026-09-08.md)，再接入新入口。

本机是部署 CoralBay 的服务器。来源选择属于当前产物；原始节点订阅、配置文件、分流规则、图标、DNS 分别追溯。切换来源不会把 666OS 的规则换成 MetaCubeX 同名规则。

### 本版必须交付

1. 两资源页使用同一套状态用语：已验证、未同步、损坏、检查失败、不可比较；缺失入口不隐藏。
2. 九项已确认问题修复，并有对应回归。
3. 四入口统一来源控件、结果来源说明；不支持的客户端组合说明原因。
4. MihomoPro 覆写与完整配置成对生成，真实规则 URL 指向所选同版本来源。
5. 普通内置分流方案支持从本机或上游读取同提交原始 MRS，转换为完整内嵌规则；保留旧模式。
6. MetaCubeX 显式修复、历史资源元信息、磁盘用量提示；有效固定版本继续保留。
7. 说明、安装与升级指南、测试记录和版本发布信息更新。

### 能力边界

- PPanel 先保证已有 Clash/Mihomo/OpenClash/Stash 原始 MRS 模板双源等价；其他格式依据具体资源映射逐项开放，不以替换域名冒充适配。
- 普通转换首批对内置 MihomoPro 的 Clash/Mihomo 与 Stash 完整 YAML 提供双源；其余客户端、第三方 INI 保持原有方式并说明未适配原因。88 个第三方配置的全部嵌套依赖递归镜像不作为本版已完成功能。
- 已验证内置 Mihomo 的 MRS 导出能力：`convert-ruleset domain mrs` 能导出原始集合的文本表示。新普通转换据此获得原始 MRS 的完整覆盖；旧 `_converted` 文件和旧 INI 不批量改写。
- 导入导出整个离线资源包、全局切换全部旧订阅、无条件自动回退、自动删除历史引用资源不在本版范围。
- Stash 字段适配与结构检查必须完成；原生客户端测试有独立结果，未获得真机结果的能力明确标注待验收。

## 用户流程

### 资源页

每项资源固定显示“本机镜像”“上游原文件”“详情”。本机缺失显示状态及同步／修复入口；不能消失，也不能给坏链接贴“可用”。详情仅以实际验证的原件作为可用和摘要比较依据；关联 geo 内容单独说明。查看本地不联网，检查上游不切换本机发布版本。

### 四个使用入口

| 入口 | 来源选择的实际作用 | 保存／交付 |
| --- | --- | --- |
| MihomoPro 覆写 | 完整配置中的 MRS 地址；覆写下载所选完整配置 | 固定版本、来源各自独立的覆写与配置 URL；专属客户端文件避免相互覆盖 |
| PPanel 模板 | 模板内受支持原始规则的下载 URL | 预览、打开、下载、复制为同一变体；原始／改造模板版本独立 |
| 普通内置转换 | 生成时从本机或固定提交上游读取 MRS，再转为内嵌规则 | 来源参数加入签名；参数改变生成新链接，旧链接继续原行为 |
| 自定义分流 | 客户端从本机或同提交上游获取 MetaCubeX YAML 集合 | 方案主动保存后原固定订阅链接继续使用；缺省字段保持旧内嵌行为 |

普通转换的“配置文件来源”保留在高级设置中；“分流规则来源”在主要设置区。仅节点输出不需要规则来源。解析旧链接时不自动补上新默认值。新建支持的方案默认本机镜像。

结果显示规则库、实际读取来源、版本、生成时间、条目数、未覆盖项、交付方式。内嵌输出明确标识“生成时读取规则，客户端随订阅更新”；不能将其写成客户端直接下载上游文件。

## 后端实现

### A. 资源身份和健康状态

- 资源身份由规则库、固定提交、路径、格式与摘要共同确定。
- 本机状态必须由实际文件的长度和 SHA-256 校验得出。666OS 详情、固定下载与关联 geo 核验共用逻辑。
- 普通转换依赖识别覆盖受管理的本机原生、派生和固定资源；同域未知路径显示待确认。
- MetaCubeX 旧规范化摘要只作追溯；原件未验证时不可比较。

### B. 修复与同步

- MetaCubeX 清单损坏时，显式修复可利用经过内容寻址校验的快照、原始文件或已知提交重建；保留损坏清单用于诊断。
- 版本 API 失败仍允许补齐已知提交原件，且保留版本检查失败提示；不擅自改规则版本。
- 整批文件与清单验证完成后再发布。失败候选不成为活动资源，也不无限积累。
- 新增修复和历史资源查询入口。历史恢复如无法证明完整性则拒绝；666OS 沿用已有回滚能力。
- 磁盘占用与保留版本数量展示告警。此版不自动清理已交付版本。

### C. MihomoPro 与 PPanel

- 覆写初始化完整节点提供者，主／备用订阅只在实际填写时使用；名称和策略组引用一致。
- 666OS 发布 ID 包含实际 YYDS 配置摘要，确保单独配置更新与备用配置恢复可发布。
- 固定留存完整配置和覆写依赖。两个来源保留同一规则集、顺序、策略，仅改变受管理规则的 URL。
- MihomoPro 使用来源与版本专属的客户端配置文件，保证切换能更新对应文件，不改写其他配置。

### D. 普通转换

- 新增可选 `rule_source=local|upstream`。缺省或兼容模式不改变旧参数及签名计算。
- 内置新模式按同一固定 666OS 版本构建；本机只读验证过的原始 MRS，上游读取该提交对应原件并核对摘要。
- 用镜像内固定的 Mihomo 内核解码 MRS，转换原生规则并内嵌；校验原始集合数量、策略引用和最终兜底。未知无法保持语义的条目必须报错，不能忽略。
- 原始 MRS 的解码缓存按内容摘要与类型隔离。转换后端通过已认证的内部代理读取精确匹配的内置策略组 INI；应用在转换后按验证过的原件注入完整规则，避免后端遗漏或旧 Stash 转换覆盖。内部入口不读取任意文件，不含用户节点凭据。
- 源参数不得直接透传为任意下载 URL。签名、缓存、历史解析均包含来源选项。
- 16 MiB 转换结果和 2 MiB 远程配置采用上限加一读取，超限拒绝；远程配置格式异常保留最后有效缓存；同步并发避免临时文件互相覆盖。

### E. Stash 节点

- 输入将 HY2 `auth/up-speed/down-speed` 与内部字段规范化，冲突拒绝。
- TUIC 版本显式校验；目标输出恢复对应客户端规范字段。
- Mihomo 和 Stash 字段不得未经转换混用；未支持扩展仍明确报错。

## 前后端契约

- 普通预设：`rule_source_options=[{id,label,available,reason,description,targets}]`、`rule_source_note`、`rule_delivery`。
- 普通生成结果：`rule_source_metadata={library,source,actual_source,revision,rule_revision,delivery,count,uncovered,resources,warnings}`。
- MihomoPro：`GET /api/resources/666os/mihomopro`，返回来源变体及 `config_url/overwrite_url`、来源可用性、版本和摘要。
- 固定 MihomoPro 变体复用 `/_rule-templates/666os/{revision}/{source}/{client}`，client 为 `mihomopro-config` 或 `mihomopro-overwrite`。
- MetaCubeX：`POST /api/routing/rules/repair`、`GET /api/routing/rules/versions`；修复历史资源不擅自切当前版本。
- 元信息接口要求登录；管理操作沿用现有请求来源与操作令牌验证。公开地址仅提供已验证的公共规则和配置产物。

## 工作拆分与执行顺序

1. 资源修复、666OS/MihomoPro、统一前端、普通转换后端四部分并行；文件归属明确，接口先约定。
2. 集成 Stash 字段适配与全链路响应元信息，建立审查问题回归。
3. 隔离环境完成资源同步、源切换、普通转换后端和客户端内核验证。
4. 最终页面验证、文档更新、版本构建；通过后提交、发布镜像及 release。
5. 线上升级先核对可用登录、备份与当前版本，保留原数据；升级后检查订阅、镜像及页面脚本版本。缺少登录不能宣称已升级。
